#   fast — 무인·병렬·안정. 자사몰 대량 처리. 안티봇 걸리면 시도 없이/시도 후 blocked로 남김.

# 3단계 분리(크롤링→LLM→DB)로:

# (1) fast 자사몰 대량 처리 — 동시성 기본 4, 올려도 ≤10(브라우저 상한 10, 100 절대 금지)

# (2) uc 크롤링만 — 3단계 분리 1단계. 워밍업 먼저(1.5와 공유, 이미 했으면 생략).
#     크롤링 결과(detail_crawled*.jsonl)는 LLM 결과와 별도 파일로 영구 보존 — 나중에 프롬프트
#     고쳐서 LLM만 다시 돌려도(FORCE_RELLM=1) 재크롤링 불필요.

python3 -m gonggu.enrich_detail.warmup_naver_uc
UC_LOGIN_WAIT=0 DETAIL_MODE=uc python3 -m gonggu.enrich_detail.crawl_stage

# (3) LLM만 — 브라우저와 무관, 고동시성(기본 60)으로 크롤링 결과를 몰아서 처리

FORCE_RELLM=1 python3 -m gonggu.enrich_detail.llm_stage        # 프롬프트 수정 후 이미 처리된 것까지 전부 재처리

# (4) DB 반영만
python3 -m gonggu.enrich_detail.load_stage

# ── (2)-샤딩 버전 — 백로그가 커서 위 (2)가 너무 느릴 때만, 쓸 수도 안 쓸 수도 있음 ──

#   병렬(각자 다른 UC_PROFILE). crawl_stage.py가 2026-08-18부터 샤드 파일 전체(detail_crawled*.jsonl)를
#   합쳐서 중복 체크하므로, 아래처럼 샤딩했다 안 했다 오가도 이미 크롤링된 건 안전하게 건너뛴다.
